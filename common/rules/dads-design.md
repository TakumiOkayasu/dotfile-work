# DADS Design Baseline

デジタル庁デザインシステム(DADS)の基本デザインを,デザイン作業の必須基準とする.
任意の参考資料でも,完成後だけに行う監査でもない.

## 適用

- ユーザーが明示的にDADSを指定しなくても,UI,画面,Webサイト,プロトタイプの視覚設計・実装・変更・レビューに適用する. デザイン機能の直接呼び出しも対象とする.
- 特定の製品名・スキル名・内部コマンドに依存しない. 利用可能な既存デザイン機能を使い,その確認・案選択・実装手順を迂回しない.
- API/DB設計やソフトウェアアーキテクチャだけの作業には適用しない. 静止画や非Web成果物では関連する視覚基準を適用し,操作・DOM等の対象外項目は理由を示す.
- 既存ブランド,参考画像,外部スキルの作風を理由にDADSを暗黙に任意化しない. 指示の競合はruntimeのinstruction hierarchyに従って報告し,必要な例外は対象・理由・承認を明示する. 逸脱を含む成果物をDADS準拠と呼ばない.
- 変更対象とその影響範囲を検証する. DADS対応を口実に無関係な画面や機能まで改修しない. 未調査の既存箇所を含むシステム全体の準拠は宣言しない.

## 設計前

1. このruleを読み,目的,対象ユーザー,成果物,既存トークン・コンポーネント,変更範囲を確認する. 既に与えられた情報を質問し直さない.
2. 下記8領域から適用項目を選び,該当する公式ページの概要・アクセシビリティ・トークンを読む. この要約だけを公式仕様の全量として扱わない. URL,確認日,採用項目と実装上の対応を記録する.
3. 公式の必須・推奨・作例を区別する. 必須は満たし,推奨を採用しない場合は根拠を残す. 作例の値を普遍的な必須値へ変換しない. 色値やトークン名を記憶から捏造しない.
4. 配色・文字・余白・状態表現を基準に沿って決めてから,案の生成や実装を行う. 既存資産は適合を確認して再利用する. DADS導入を理由に依存,フォント配信,独自CSS基盤を無断追加しない.
5. 公式資料を取得できない場合は取得不能と確認済み範囲を示す. 確認済み基準で進める範囲と保留項目を分離し,最新仕様への適合を推測で補わない.

## 基本デザインの確認項目

確認日: 2026-09-06. 一次資料は[基本デザイン](https://design.digital.go.jp/dads/foundations/)および下記リンク. 公式更新時は差分を確認し,このruleと検証項目を同時に更新する.

| 領域 | 設計・検証の基準 | 公式資料 |
| --- | --- | --- |
| カラー | キー・共通・機能・セマンティックカラーの役割を守る. テキストはサイズを問わず背景と4.5:1以上,識別に必要な非テキストUIは隣接色と3:1以上を確認する. 公式の適用除外は個別に根拠を残す. 状態を色だけで伝えない. フォーカスはYellow-300とBlackの2重構造を維持し,色を変更しない. | [概要](https://design.digital.go.jp/dads/foundations/color/), [アクセシビリティ](https://design.digital.go.jp/dads/foundations/color/accessibility/) |
| タイポグラフィ | 用途に対応するDADSの文字スタイルとサイズ・ウェイト・行高を選ぶ. Noto Sans JP等に加えシステムフォントも許容されるため,Webフォント取得を必須にしない. 読みやすい行長・行間と200%拡大時の可読性・操作性を確認する. | [概要](https://design.digital.go.jp/dads/foundations/typography/), [文字スタイル](https://design.digital.go.jp/dads/foundations/typography/text-style/), [アクセシビリティ](https://design.digital.go.jp/dads/foundations/typography/accessibility/) |
| アイコン | ラベルと併用し,重複する装飾アイコンの読み上げを避ける. リンクのラベルとアイコンを別の操作対象にしない. やむを得ず単体で使う場合は代替ラベルを付け,操作対象を44x44 CSS px以上にする. 背景と4.5:1以上を基本とし,非テキスト専用と保証できる場合のみ3:1以上を認める. | [概要](https://design.digital.go.jp/dads/foundations/icon/), [アクセシビリティ](https://design.digital.go.jp/dads/foundations/icon/accessibility/) |
| レイアウト | マージン・カラム・ガターと読み順を設計し,モバイル・PC・拡大表示で検証する. 視覚順序とDOM・フォーカス順序を整合させる. 12カラムや768pxのブレークポイントは作例であり固定しない. 内容の切捨てやoverflowの隠蔽で崩れを解消しない. | [概要](https://design.digital.go.jp/dads/foundations/layout/), [アクセシビリティ](https://design.digital.go.jp/dads/foundations/layout/accessibility/) |
| リンクテキスト | 遷移先・目的が分かる文言と,色以外の識別手段を備える. 通常・訪問済み・hover・active・focusを区別する. 新規タブや非HTML文書の情報を必要に応じて示す. ターゲットは24x24 CSS pxを目安に,公式のサイズ・間隔・例外条件で評価する. 外部リンク全件を新規タブにする作例は強制しない. | [概要](https://design.digital.go.jp/dads/foundations/link-text/), [アクセシビリティ](https://design.digital.go.jp/dads/foundations/link-text/accessibility/) |
| 余白 | 関連性,グループ,情報階層が伝わる余白を選び,採用したスケールを一貫して使う. 8pxは一般的な基準単位の例で,すべての余白をその倍数に固定しない. 空白文字による位置合わせではなくレイアウトで表現する. | [概要](https://design.digital.go.jp/dads/foundations/spacing/), [アクセシビリティ](https://design.digital.go.jp/dads/foundations/spacing/accessibility/) |
| 角の形状 | none/small/medium/large/fullの意図とコンポーネントの大きさ・縦横比に合わせて形状を選び,一貫性を確保する. 作例の半径を全コンポーネント共通の固定値にしない. | [概要](https://design.digital.go.jp/dads/foundations/corner-shapes/) |
| エレベーション | 要素の階層と重なりを表現するために使い,影を装飾だけで乱用しない. オーバーレイ上の要素にもボーダーを設ける(透明色も可). 強制カラーモードで境界が消えないことを確認する. ダークモード用の公式作例があると仮定せず,実際の配色と階層で検証する. | [概要](https://design.digital.go.jp/dads/foundations/elevation/), [アクセシビリティ](https://design.digital.go.jp/dads/foundations/elevation/accessibility/) |

## 設計・実装中

- 既存デザイン機能やsubagentへ委譲する前に,目的・変更範囲・適用するDADS基準・一次資料・採用トークン・例外・検証条件を渡す. 連携先がこのruleを自動継承したと仮定しない.
- 必要な画面状態(エラー,無効,選択,hover,focus等)も設計する. 使用するコンポーネントの操作要件は該当する公式コンポーネント資料で確認し,基本デザインだけで操作要件まで網羅したとみなさない.
- 既存のテスト・アクセシビリティ検査を再利用する. 連携先の自己申告だけで完了せず,親が成果物と根拠を照合する.

## 出力前

1. 8領域を棚卸しし,各項目に`passed` / `failed` / `unverified` / `not-applicable`を付ける. 判定には公式の該当箇所,成果物上の対象,検証方法・結果を対応付ける. 対象外にも理由を残す.
2. 実際の色の組合せと状態ごとのコントラスト,モバイル・PC表示,文字拡大,キーボード操作,フォーカス,読み上げ用の名前・順序を適用範囲で確認する. スクリーンショットや静的コードだけで操作・読み上げまで検証済みにしない.
3. 違反は承認済み範囲で修正し再検証する. 未解決の違反や未検証を準拠済みと報告しない. 検証手段がない項目を`not-applicable`へ振り替えない.
4. 最終報告は適用範囲,根拠付き結果,例外,残件を示す. DADS基本デザインの確認と,WCAG/JISの適合試験・第三者認証を混同しない.

## 運用境界

このruleは設計時の指示と検証契約であり,モデルの遵守を機械的に保証するものではない. 配布テストの成功だけで成果物のDADS準拠を宣言しない. この設定を読み込む実行環境が対象であり,別端末やクラウドへの自動同期は前提にしない.
